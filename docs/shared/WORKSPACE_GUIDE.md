# Workspace Guide — Two Repositories, One Project

> This file is the workspace-root `AGENTS.md`. The canonical copy lives in
> both repositories at `docs/shared/WORKSPACE_GUIDE.md`; the copy in the
> workspace folder is generated by `scripts/setup-workspace-root.sh`.
> Edit the copy in `docs/shared/`, never only the root copy (the workspace
> folder is not under version control).

## You are in the workspace folder, not in a repository

This folder (usually `crmNative/`) holds ONE project made of TWO separate git
repositories. It is NOT a monorepo and NOT a git repository itself.

```
crmNative/                         <- you are here (not a git repo)
├── AGENTS.md                      <- this guide (generated)
├── rajat_crm_node_backend/        <- git repo 1: REST API (Node/Express/Prisma/PostgreSQL)
├── rajat_crm_native_frontend/     <- git repo 2: app (Expo/React Native: Android, iOS, web)
├── .agents/                       <- generic "AG Kit" toolkit for Google Antigravity (not project docs)
├── .claude/                       <- Claude Code local settings
├── SERVER_README.md               <- LEGACY server notes, superseded by docs/shared/INFRASTRUCTURE_AND_DEPLOY.md
├── APK_BUILDS.md                  <- copy of rajat_crm_native_frontend/APK_BUILDS.md
└── screenshot/                    <- reference images (e.g. the client's paper invoice template)
```

| # | Repository | What it is | Branches |
|---|---|---|---|
| 1 | `rajat_crm_native_frontend` | The CRM app for Rajat Electricals: Expo SDK 54, React Native, Expo Router, TypeScript | `dev_01` (development), `main` (production) |

## Start here

1. Read the whole-system docs ONCE from either repo — `docs/shared/` is
   identical in both. Start with `rajat_crm_node_backend/docs/shared/README.md`
   (reading order) and `docs/shared/RULES.md`.
2. Then read the `AGENTS.md` of every repo you will change:
   - `rajat_crm_node_backend/AGENTS.md`
   - `rajat_crm_native_frontend/AGENTS.md`
3. Check both repos before you start:
   ```bash
   git -C rajat_crm_node_backend status -sb
   git -C rajat_crm_native_frontend status -sb
   ```
   Both should be on `dev_01`.

## Rules for working across both repositories

1. **Run git inside each repository** (`git -C <repo> ...` or `cd <repo>`).
   Never run `git init` in this workspace folder and never create project
   files here — they would not be versioned. Only the generated guide files
   belong here.
2. **One task, two commits.** A change that touches both repos is committed in
   each repo separately, both on `dev_01`, with matching messages. Never amend
   or force-push (the owner pushes from these same checkouts).
3. **API changes are two-sided.** When a backend route or response shape
   changes, update `rajat_crm_native_frontend/services/api.ts` (functions and
   types) in the same task.
4. **Release order: backend first, then frontend.** Never ship an app build
   that calls endpoints production does not have yet.
5. **`docs/shared/` must stay identical in both repos.** After editing it in
   one repo, copy it to the other and run `scripts/check-shared-docs.sh`
   (exits 0 when identical).
6. **Document every task** per `docs/shared/DOCUMENTATION_PROTOCOL.md`: update
   the stale docs, add a `docs/shared/WORK_LOG.md` entry with both repos'
   commit hashes, mirror `docs/shared/`.
7. **Read `SERVER_README.md` only as history** — current server/deploy facts
   are in `docs/shared/INFRASTRUCTURE_AND_DEPLOY.md`.
8. Everything written into the repositories is English; talk to the owner in
   the language they use.
9. **Finish with `npm run verify`** (in either repo, after committing). It
   checks both repos — git state, docs, project rules, TypeScript, the backend
   API tests — and must end with `PASSED`. A backend bug fix comes with a test
   in `rajat_crm_node_backend/test/` (`npm test`).

## Running both locally

```bash
# terminal 1 — API (see docs/shared/LOCAL_DEV_AND_TESTING.md before using a real .env)
cd rajat_crm_node_backend && npm install && npx prisma generate && npm run dev     # PORT from .env, usually 3001

# terminal 2 — app
cd rajat_crm_native_frontend && npm install && npx expo start --web              # .env: EXPO_PUBLIC_API_URL=http://localhost:3001
```

## Rebuilding this workspace on a new machine

```bash
mkdir crmNative && cd crmNative
git clone https://github.com/ProjectsAcademy/rajat_crm_node_backend.git
git clone https://github.com/ProjectsAcademy/rajat_crm_native_frontend.git
git -C rajat_crm_node_backend checkout dev_01
git -C rajat_crm_native_frontend checkout dev_01
rajat_crm_node_backend/scripts/setup-workspace-root.sh   # writes AGENTS.md + AI pointer files here
```

Then create each repo's `.env` (ask the owner for values; never commit them).
